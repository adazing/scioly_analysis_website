  • Example Creation of Available Events CSV Data Using Google Sheets:

  • Step 1: Make data. Requirements:

    • There is no header.
    • All available events must be mentioned once, and there must not be any repeats.
    • Each row corresponds to a group of events that are similar.
    • All events mentioned should be formatted in the same way as the other data.
    • Each row is assumed to end as soon as it reaches an empty cell. Therefore, all events on each row should be stated in the first cell and leave no blank cells between until the end is reached.
    • There is no limit to row length or row number.
    • Any event with three members (default is two) should be indicated as such with a "(3)" next to the name.
    • There should be no other information in the sheet.

  • Step 2: Download CSV data.

  • Example Creation of Conflicting Events CSV Data Using Google Sheets:

  • Step 1: Make data. Requirements:

    • There is no header.
    • Not all events need to be mentioned, but there should be no repeats of the mentioned events.
    • Each row corresponds to a group of events that are in the same timeblock. Therefore, no one can do both of the events at the same time.
    • Each row is assumed to end as soon as it reaches an empty cell. Therefore, all events on each row should be stated in the first cell and leave no blank cells between until the end is reached.
    • There is no limit to row length or row number.
    • There should be no other information in the sheet.

  • Example Creation of Member Event Preferences CSV Data Using Google Sheets:

  • Step 1: Make data. Requirements:

    • All members that want to be on the competition should be present with no repeats.
    • Members can have different tags according to their status. A member can have "(O)" next to their name to say that they are an officer and get absolute priority when being assigned (automatically placed in the best team possible). If they have "(R)" (mutually exclusive with "(O)"), the member is required to be on one of the many events, though they are not given absolute priority. Any member can also have the "(S)" tag, signaling that they are seniors and the 7-senior rule applies to them.
    • First line contains the header. (What is in the header does not matter and it can be completely empty, but the first row should not have data.)
    • All members must be stated in the A column and should be strings. Only letters will be taken into account. Uppercase/lowercase does not matter. Make sure that the way you named the nenber is the same as in all the other data.
    • Each member may have a list of preferences that are ranked. There is no specific number of events they must rank, and it can change with each member. Alternatively, each member can have no ranked preferences, meaning the teams are decided solely on skill level. The event names should be stated as strings, and only letters will be taken into account. Uppercase/lowercase does not matter. Make sure that the way you named the event is the same as in all the other data.
    • The events do not need to be in any order, and there is no max number of events.
    • A "(*)" next to an event indicated that the member is required to be put on that event, if possible.
    • Colors/formatting does not matter.
    • There should be no other data in the file except that of which is explained above.

  • Step 2: Download CSV data.
    File -> Download -> Comma Separated Values (.csv) {% comment %} {% endcomment %}
