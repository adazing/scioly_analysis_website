Problem #1: Assigning Skills to Event Member pairs

Key

\(C={c_1,c_2...c_n}\): Set of competitions
\(P={p_1,p_2...p_z}\): Set of practice tests/tryouts
\(X={x_1,x_2...x_y}\): Set of instances (both practice tests/tryouts and competitions)
\( \mathcal{M_x} \): Set of all event member pairs \((m, e)\) in instance \(x\)
\( rank(m, e, c) \): rank of member \(m\) in event \(e\) in competition \(c\)
\( total\_teams(c) \): total number of teams in competition \(c\)
\( points\_scored(m, e, p) \): total number of points scored in practice test/tryout \(p\)
\( max\_points(p) \): maximum number of points a person can score on practice test/tryout \(p\)
\( experience(m, e, x) \): number of times member \(m\) had participated in event \(e\) before and during instance \(x\) (either a competition \(c\) or a practice test \(p\))
\(discovered\_experience\_rate\): A parameter optimized during the loss minimization, represents the slope of the linear growth in skill as experience increases
\(adjustable\_experience\_rate\): A parameter that can be changed by the user, represents the slope of the linear growth in skill as experience increases

Event-Member Mapping

For each \(c \in C\) or \(p \in P\).
\(score(m, e, c)\): Normalized score for event \(e\) and member \(m\) in either a competition or practice test/tryout:
For a competition \(c\) : $$score(m, e, c)=1-\frac{rank(m, e, c)}{total\_teams(c)}$$
For a practice test/tryout \(p\) : $$score(m, e, p)=\frac{points\_scored(m, e, p)}{max\_points(p)}$$

Experience-Based Adjustments

Now, define the adjusted score for event \(e\) and member \(m\) during instance \(x\) (either a competition \(c\) or practice test \(p\)) as: $$adj\_score(m, e, x) = score(m, e, x) - discovered\_experience\_rate \cdot experience(m, e, x)$$

Instance Weighting

Each instance \(x\) is associated with:

  • Weight \(w_x > 0 \), and
  • Bias \(b_x\)
Final adjusted score: \(final\_score(m, e, x) = w_x \cdot adj\_score(m, e, x) + b_x \)

Leave-One-Out Loss Function

For each instance \(x_k\) left out:

  1. Calculate predictions using scores from other competitions $$ pred\_final\_score(m, e, x_k) = \frac{1}{|X\text{ } \backslash\{x_k\}|} \sum_{x \in X\text{ } \backslash\{x_k\}} final\_score(m, e, x)$$ $$ \text{of if } X\text{ } \backslash\{x_k\} =\emptyset \text{ , then } pred\_final\_score(m, e, x_k) = 0$$ $$ pred\_adj\_score(m, e, x_k) = \frac{pred\_final\_score(m, e, x_k) - b_{x_k}}{w_{x_k}}$$ $$ pred\_score(m, e, x_k) = pred\_adj\_score(m, e, x_k) + discovered\_experience\_rate \cdot experience(m, e, x_k)$$
  2. Loss for \(x_k\): $$ loss(x_k) = \frac{1}{|\mathcal{M}_{x_k}|} \sum_{(m, e) \in \mathcal{M}_{x_k}} (score(m, e, x_k) - pred\_score(m, e, x_k))^2$$
Total loss: $$Total\_Loss = \frac{1}{|X|} \sum_{x_k \in X} loss(x_k)$$

Minimize the Total Loss with Respect to:

  • \({\{w_x, b_x\}}_{x \in X} \)
  • \(discovered\_experience\_rate\)
  • \(s_0\)

Calculating Outputs

  • instances without overlapping event, member pairs \((m, e)\) are given the average weight (\(w_{avg}\)) and bias (\(b_{avg}\)) of the other instances with overlapping pairs
  • Each member's skill is incrementally updated based on their event performance $$pred\_final\_score(m, e, x_{y+1})= \frac{1}{|X|} \sum_{x \in X} final_score(m, e, x)$$ $$pred\_adj\_score(m, e, x_{y+1})=\frac{pred\_final\_score(m, e, x_{y+1}) - b_{avg}}{w_{avg}}$$ $$pred\_score(m, e, x_{y+1})= pred\_adj\_score(m, e, x_{y+1}) + adjustable\_experience\_rate \cdot experience(m, e, x_{y+1}) $$
  • Scale the predicted scores appropriately, making \(Skill(m, e)\)

Problem #2: Generating Teams

Key

\(T\): current team assignment where \(T(e)\) is the set of members assigned to event \(e\)
\(A(T)\): set of unique members assigned to events on the team \(T\)
\(M\): set of all available members
\(E\): set of all available events
\(E_3\): set of events with a maximum of 3 members (instead of the usual 2)
\(worst\_preference\_amount \): maximum number of preferred events any member listed
\(P(m,e)\): rank of preference member \(m\) listed for event \(e\), if it is not listen then it is \(worst\_preference\_amount + 1\) (ex. if Mary has Astronomy as 1st preference, then \(P(Mary, Astronomy)=1\) )
\(Skill(m, e)\): skill score of member \(m\) in event \(e\) (covered in the previous section)
\(X\): set of pairwise member-event \((m, e)\) constraints, where member \(m\) must be placed on event \(e\)
\(R(T)\): set of unique members who are required to be on the team \(T\)
\(Y\): set of member-member-event triples \((m_1, m_2, e)\), which means members \(m_1\) and \(m_2\) want to be partners for event \(e\)
\(C(e)\): set of events conflicting with event \(e\)
\(B\): set of build events
\(s(m)\): boolean indicator if member \(m\) is a senior
\(max\_size\): maximum team size
\(max\_events\_per\_member\): maximum number of events per member
\(max\_build\_events\_per\_member\): maximum number of build events per member
\(min\_events\_per\_member\): minimum number of events per member
\(events\_done(T, m)\): number of event member \(m\) has on team assignment \(T\)
\(w\): parameter that can be changed by the user, if it is closer to 1, then it values skill more over preferences and vice-versa.

Team Validity Constraints

Define \( f(T, m, e) \) to check if adding member \( m \) to event \( e \) in team \( T \) is valid:

  • Event Capacity: Each event \( e \) can have at most \( k \) members, where \( k = 2 \) for standard events and \( k = 3 \) for events that explicitly allow three members. \[ |T(e)| < \begin{cases} 2 & \text{if } e \notin E_3, \\ 3 & \text{if } e \in E_3. \end{cases} \]
  • Unique Assignment: A member \( m \) cannot already be assigned to event \( e \). \[ m \notin T(e). \]
  • Maximum Events per Member: Each member \( m \) can only participate in a limited number of events, defined as \( max\_events\_per\_member \). \[ |\{e \in E : m \in T(e)\}| < max\_events\_per\_member. \]
  • Maximum Build Events per Member: A member \( m \) can only participate in at most \( max\_build\_events\_per\_member \) build events \( B \). \[ |\{e \in B : m \in T(e)\}| < max\_build\_events\_per\_member. \]
  • Conflict-Free Scheduling: A member \( m \) cannot be assigned to events \( e_1 \) and \( e_2 \) that conflict in schedule. \[ \forall e' \in C(e), m \notin T(e'). \]
  • Max Team Size: There cannot be more than \(max\_size \) members on a team \(T\) \[ |A(T)| \le max\_size \]
  • Senior Constraint: There can be at most 7 seniors (where \( s(m) = 1 \)) across all events in the team. \[ |\{m \in M : s_m = 1, m \in T(e) \}| \leq 7. \]
Validity Check: To check if assigning \( m \) to \( e \) is valid, evaluate: \[ f(T, m, e) = \text{True if all constraints above are satisfied, False otherwise.} \]

Team Scoring Function

Define the team score \(Score(T)\) as a combination of preference scores \(Score_P\) and skill scores \(Score_K\):

  • Preference Score: $$Score_P(T)=\sum_{e \in E} \sum_{m \in T(e)} \frac{worst\_preference\_amount - P(m, e) + 1}{worst\_preference\_amount}$$
  • Skill Score: $$Score_K(T)=\sum_{e \in E} \sum_{m \in T(e)} Skill(m, e) $$
  • Partner Preferences Bonus: $$Score_K(T)+=\sum_{e \in E} \sum_{(m_1, m_2, e) \in Y} I(m_1 \in T(e) \land m_2 \in T(e))$$
  • Required Pairs Bonus: $$Score_K(T)+=\sum_{(m,e) \in X} \begin{cases} 10000 & \text{if } m \in T(e), \\ 0 & \text{otherwise}. \end{cases} $$
  • Final Team Score: $$Score(T) = w \cdot Score_K(T) + (1-w) \cdot Score_P(T)$$

Optimization Problem

  1. Find Optimal Event Addition:
    Define a function \(max_e(T, m, is\_necessary)\):
    • For a member \(m \in M\), iterate over all \(e \in E\)
      • if \(f(T, m, e)=True\), create \(T'\), which has member \(m\) added to \(T(e)\)
      • if \(f(T, m, e)=False\), record \(Score_{orig}=Score(T)\), then iterate over all members \(m_o \in T(e)\)
        • If \(events\_done(T, m) > min\_events\_per\_member \): Define a \(T'\), which has \(m_o\) removed from \(T(e)\). If \(f(T', m, e)=True\), then add member \(m\) to \(T'(e)\). Define \(Score_{new}=Score(T')\).
          • If \(is\_necessary=False\), then consider replacing \(m_o\) with \(m\) in \(T(e)\) as valid only if \(Score_{new}-Score_{old} \ge 0\)
          • Otherwise, then always consider replacing \(m_o\) with \(m\) in \(T(e)\) as valid (even when \(Score_{new}-Score_{old} < 0\))
    The output of \(max_e(T, m, is\_necessary)=T^*\), where \(T^*\) is the \(T'\) (team with event addition or member replacement) which maximizes \(Score(T')\).
  2. Find Optimal Member Addition:
    Define a function \(max_m(T, available\_member\_set)\):
    • For a team \(T\), iterate over all members not already on the team (\(m \in available\_member\_set \backslash A(T)\)).
      • Define \(T^@=T\)
      • Repeat until \(events\_done(T^@, m)==min\_events\_per\_member\):
        • \(T^@=max_e(T^@, m, True)\)
        Repeat until \(events\_done(T^@, m)==max\_events\_per\_member\)
        • If possible, \(T^@=max_e(T^@, m, False)\)
    The output of \(max_m(T, available\_member\_set)=T^\#\), where \(T^\#\) is the \(T^@\) (team with member addition) which maximizes \(Score(T^@)\).
  3. Make a Team:
    • Start with empty \(T\)
    • using \(max_m(T, R(T))\) exactly \(|R(t)|\) times, fill the events with required members (people that need to be on the team \(T\))
    • using \(max_m(T, M)\) exactly \(max\_size-|R(T)|\) times, fill the events with any other available members

If you have ideas on how to improve the algorithm, please contact us!
