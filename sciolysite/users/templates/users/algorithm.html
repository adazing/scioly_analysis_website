Problem #1: Assigning Skills to Event Member pairs

Key

\(C={c_1,c_2...c_n}\): Set of competitions
\(P={p_1,p_2...p_z}\): Set of practice tests/tryouts
\(X={x_1,x_2...x_y}\): Set of instances (both practice tests/tryouts and competitions)
\( \mathcal{M_x} \): Set of all event member pairs \((e, m)\) in instance \(x\)
\( rank(e, m, c) \): rank of member \(m\) in event \(e\) in competition \(c\)
\( total\_teams(c) \): total number of teams in competition \(c\)
\( points\_scored(e, m, p) \): total number of points scored in practice test/tryout \(p\)
\( max\_points(p) \): maximum number of points a person can score on practice test/tryout \(p\)
\( experience(e, m, x) \): number of times member \(m\) had participated in event \(e\) before and during instance \(x\) (either a competition \(c\) or a practice test \(p\))
\(discovered\_experience\_rate\): A parameter optimized during the loss minimization, represents the slope of the linear growth in skill as experience increases
\(adjustable\_experience\_rate\): A parameter that can be changed by the user, represents the slope of the linear growth in skill as experience increases

Event-Member Mapping

For each \(c \in C\) or \(p \in P\).
\(score(e, m, c)\): Normalized score for event \(e\) and member \(m\) in either a competition or practice test/tryout:
For a competition \(c\) : $$score(e, m, c)=1-\frac{rank(e, m, c)}{total\_teams(c)}$$
For a practice test/tryout \(p\) : $$score(e, m, p)=\frac{points\_scored(e, m, p)}{max\_points(p)}$$

Experience-Based Adjustments

Now, define the adjusted score for event \(e\) and member \(m\) during instance \(x\) (either a competition \(c\) or practice test \(p\)) as: $$adj\_score(e, m, x) = score(e, m, x) - discovered\_experience\_rate \cdot experience(e, m, x)$$

Instance Weighting

Each instance \(x\) is associated with:

  • Weight \(w_x > 0 \), and
  • Bias \(b_x\)
Final adjusted score: \(final\_score(e, m, x) = w_x \cdot adj\_score(e, m, x) + b_x \)

Leave-One-Out Loss Function

For each instance \(x_k\) left out:

  1. Calculate predictions using scores from other competitions $$ pred\_final\_score(e, m, x_k) = \frac{1}{|X\text{ } \backslash\{x_k\}|} \sum_{x \in X\text{ } \backslash\{x_k\}} final\_score(e, m, x)$$ $$ \text{of if } X\text{ } \backslash\{x_k\} =\emptyset \text{ , then } pred\_final\_score(e, m, x_k) = 0$$ $$ pred\_adj\_score(e, m, x_k) = \frac{pred\_final\_score(e, m, x_k) - b_{x_k}}{w_{x_k}}$$ $$ pred\_score(e, m, x_k) = pred\_adj\_score(e, m, x_k) + discovered\_experience\_rate \cdot experience(e, m, x_k)$$
  2. Loss for \(x_k\): $$ loss(x_k) = \frac{1}{|\mathcal{M}_{x_k}|} \sum_{(e, m) \in \mathcal{M}_{x_k}} (score(e, m, x_k) - pred\_score(e, m, x_k))^2$$
Total loss: $$Total\_Loss = \frac{1}{|X|} \sum_{x_k \in X} loss(x_k)$$

Minimize the Total Loss with Respect to:

  • \({\{w_x, b_x\}}_{x \in X} \)
  • \(discovered\_experience\_rate\)
  • \(s_0\)

Calculating Outputs

  • instances without overlapping event, member pairs \((e, m)\) are given the average weight (\(w_{avg}\)) and bias (\(b_{avg}\)) of the other instances with overlapping pairs
  • Each member's skill is incrementally updated based on their event performance $$pred\_final\_score(e, m, x_{y+1})= \frac{1}{|X|} \sum_{x \in X} final_score(e, m, x)$$ $$pred\_adj\_score(e, m, x_{y+1})=\frac{pred\_final\_score(e, m, x_{y+1}) - b_{avg}}{w_{avg}}$$ $$pred\_score(e, m, x_{y+1})= pred\_adj\_score(e, m, x_{y+1}) + adjustable\_experience\_rate \cdot experience(e, m, x_{y+1}) $$
  • Scale the predicted scores appropriately.

Key

\(S(m, e)\): skill score of member \(m\) in event \(e\) (covered in the previous section)

\(C(e)\): set of events conflicting with event \(e\)
\(B\): set of build events
\(s(m)\): boolean indicator if member \(m\) is a senior
\(max\_size\): maximum team size
\(max\_events\_per\_member\): maximum number of events per member
\(max\_build\_events\_per\_member\): maximum number of build events per member
\(min\_events\_per\_member\): minimum number of events per member
\(w\): parameter that can be changed by the user, if it is

Define \( f(T, m, e) \) to check if adding member \( m \) to event \( e \) in team \( T \) is valid:

  • Event Capacity: Each event \( e \) can have at most \( k \) members, where \( k = 2 \) for standard events and \( k = 3 \) for events that explicitly allow three members. \[ |T[e]| < \begin{cases} 2 & \text{if } e \notin E_3, \\ 3 & \text{if } e \in E_3. \end{cases} \]
  • Unique Assignment: A member \( m \) cannot already be assigned to event \( e \). \[ m \notin T[e]. \]
  • Maximum Events per Member: Each member \( m \) can only participate in a limited number of events, defined as \( max\_events\_per\_member \). \[ |\{e \in E : m \in T[e]\}| < max\_events\_per\_member. \]
  • Maximum Build Events per Member: A member \( m \) can only participate in at most \( max\_build\_events\_per\_member \) build events \( B \). \[ |\{e \in B : m \in T[e]\}| < max\_build\_events\_per\_member. \]
  • Conflict-Free Scheduling: A member \( m \) cannot be assigned to events \( e_1 \) and \( e_2 \) that conflict in schedule. Define \( C(e) \) as the set of events conflicting with \( e \): \[ \forall e' \in C(e), m \notin T[e']. \]
  • Senior Distribution: There can be at most 7 seniors \( (s_m = 1) \) across all events in the team. \[ |\{m \in M : s_m = 1, m \in T[e] \}| \leq 7. \]
Validity Check: To check if assigning \( m \) to \( e \) is valid, evaluate: \[ f(T, m, e) = \text{True if all constraints above are satisfied, False otherwise.} \]
